End-to-End Walkthrough — Brand-Specific Upload
Worked example: 0888-SP-ELLESSE-Recap Sample MAA Sport Licensed-Multi-SP2027-ID-1.xlsx → Stibo IIEP_ArticlePlanning
Phase 1 · Upload & Trigger
1User selects dropdowns in MAP Portal and uploads 0888-SP-ELLESSE-Recap Sample ...-SP2027-ID-1.xlsx; portal writes it to raw/metadata/ellesse/
2S3 ObjectCreated → EventBridge → validate-transform Lambda
↓
Phase 2 · Routing
3Router extracts principal ellesse; creates AuditLogger (trigger = brand_specific)
4Dispatch to ellesse.lambda_function.lambda_handler
↓
Phase 3 · File Classification & Required-File Validation
5Filename keyword match → type recap (“Recap Sample”); ETL target = recap_main Detection is order-sensitive: first matching keyword wins
6Required set = {recap, mdd, attributes}; list bucket under brand prefix + root globals, latest version wins
7All required files present? No → return 200 “waiting_for_mandatory_files” — ETL resumes automatically on the next upload
↓
Phase 4 · ETL (Ellesse recap_main)
8Download files to /tmp/stibo_workdir_ellesse; convert xlsb/csv → xlsx if needed
9Load reference data: MDD (attributes + LOVs), Attributes List tab, Ellesse MD Mapping, RNA (4-pass fuzzy join)
10Pass 1 — per article (ThreadPool, max 8 workers): map fields, resolve Gender/Age via MD mapping → MDD → LOV IDs, derive defaults from filename (0888 / SP / ELL / SP2027 / ID), validate mandatory + LOV membership
11Pass 2 — build classifications (CLH_ELLBatches → CLH_ELL_SP2027) and stream Product/Variant XML with 1 MB buffer
↓
Phase 5 · Delivery to Stibo
12Upload XML → processed/stepxml/ellesse/0888-SP-ELLESSE-....xml
13XML landing triggers send-to-step Lambda: filename regex match “recap\s*sample” → endpoint IIEP_ArticlePlanning
14OIDC client-credentials token → POST binary XML to upload-direct?fileName=…&context=Context1&workspace=Main (3 retries, exponential backoff) 4xx (except 429) → no retry, fail fast · success → bgId receipt JSON saved
↓
Phase 6 · Audit & STEP Processing
15Router flushes audit JSON → raw/logs/ellesse/{timestamp}.json (classification, downloads, article statuses, XML keys, timings)
16STEP queues the BGP behind the IIEP; processing result is visible in STEP monitoring (/restapi/integrationendpoints/{id}/log) — not yet read back automatically
